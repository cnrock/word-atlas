# Offline Android build

Artifacts: `word-atlas-offline.apk` (initial build), `word-atlas-offline-v1.0.1.apk` (launcher fix), `word-atlas-offline-v1.0.2.apk` (external-link attempt; broken offline request handler), and `word-atlas-offline-v1.0.3.apk` (recompiled WebView client; package `org.wordatlas.offline`, versionCode 4, Android 6.0/API 23+). Updates keep the original signing key so they can be installed over earlier builds while retaining user data. Launcher label is `词光`; the density-specific launcher icons are adapted from upstream `public/icon-512.png` to preserve the website's compass identity. The launcher activity explicitly declares the same label and icon.

This is the repository's Vite production bundle built with `ATLAS_BASE=/assets/`, packaged in `assets/web/` in the APK. `MainActivity` serves only that directory via intercepted `https://appassets.androidplatform.net/assets/` WebView requests. It denies all other WebView resource requests, disables file/content access, cookies, mixed content, and popup windows; the Android manifest requests no Internet permission. The website service worker is disabled for this packaged origin because all content already ships in the APK. Starting in v1.0.3, external links to the upstream GitHub repository (including documentation and data directory) use same-window navigation in the packaged site and are handed off to the phone's external browser by the WebView client; a network connection and browser are required for those links. The app itself remains offline.

Version 1.0.4 changes: the Atlas galaxy search now renders tappable matches, and the Android shell now implements WebChromeClient file selection (system document picker) and a scoped JavaScript bridge to save the learning backup through Android's system document creator. The WebView allows content URI reads for the selected document but still denies file paths, cookies, internet resources and unapproved navigation. Browser smoke tests exercise backup JSON export/import and gallery search, while javac/D8 verify native callbacks compile; a real Android device test is still outstanding. The 1.0.4 APK was signed with the original local key and verified for an in-place upgrade on Android 15. Do not publish the signing key or replace it with a different key; uninstalling loses local learning progress.

Rebuild prerequisites are in `.toolchain/` (local Temurin 17, Android API 23 platform, ARM64 aapt/zipalign shared libraries, R8, apksigner). The shell was compiled with javac and D8, including both `MainActivity.class` and its anonymous `MainActivity$1.class` WebViewClient; `package.py` rejects DEX without the request and navigation callbacks (omitting the inner class caused v1.0.2 to fail to load offline assets). The manifest was packaged with aapt, all `dist/` files inserted uncompressed to enable random-access reads, then the archive was zipaligned and signed. Source: upstream commit `e7b44629230a470e6b664826ced4af2c367b44c2` plus the Android shell and the `src/main.tsx` service-worker guard. `package.py` contains the asset packaging step and `smoke.mjs` contains a browser offline smoke test. The local signing key is retained under `build/` for future update compatibility; do not publish it or use it as a release key.

Verification performed: `npm test` (21/21), `npm run check:atlas` (7,298 words, 22,905 recordings, 0 errors), `ATLAS_BASE=/assets/ npm run build`, zipalign check, apksigner v1/v2/v3 verification, `ZipFile.testzip()` (no corruption), 37,640/37,640 `dist/` files present in the signed APK, compiled-manifest permissions inspection (no permissions), and a Chromium smoke test with all external requests blocked (app rendered, index and sample entry/image/audio succeeded, no failed requests). The browser smoke test serves the identical `dist/` tree via a localhost stand-in. Android 15 Redroid on a separate host verified the 1.0.3 → 1.0.4 in-place install and backup document picker; this is not a physical-device test.

## Sharing and store release

The next Android shell adds `ShareProvider`, a read-only `content://` endpoint for one temporary PNG in the app cache. `MainActivity` receives a PNG via the JS bridge and invokes the Android `ACTION_SEND` chooser with a temporary read grant; the web browser keeps `navigator.share` and download fallback. The shared image is not uploaded to any server, and no storage/media permission is requested. The `About` links in the Android build point to the cnrock fork and open in an external browser (the packaged app itself needs no network permission).

Only commit the `src/`, `res/`, `AndroidManifest.xml`, `package.py`, `smoke.mjs`, and this documentation under `android-offline/`. Never commit `build/`, APKs, `.toolchain/`, signing keys, or `*.idsig`. `package.py` expects a locally compiled `classes.dex` and local tools: see the manifest and Java sources; no credential is included in this repository. For reproducible store builds, provide a proper Gradle Android App Bundle pipeline, current target SDK, test on physical devices, and preserve the established signing identity for existing installations. Google Play requires an AAB rather than this APK; at ~643 MiB, Play delivery also needs an asset-delivery strategy and review of app size.

## Play App Bundle prototype (not yet a verified store release)

The `app/` + `webassets/` Gradle project targets API 36 with AGP 8.13.2, minSdk 23, application ID `org.wordatlas.offline`, and versionCode 7 (1.0.6). The WebView still loads `https://appassets.androidplatform.net/assets/` from packaged assets; `webassets` is an **install-time** Play Asset Delivery pack so offline words, pictures and recordings are available on first launch. This is a separate build pipeline from `package.py` and the existing 1.0.5 APK source. Do **not** run `package.py` on this manifest: its legacy aapt workflow expects embedded version/SDK attributes and does not produce an AAB.

Build prerequisites: Android SDK platform 36/build-tools and JDK 17, a compatible Gradle 8.13 installation and enough free disk for `dist/`, pack intermediates and the output. From repository root: `ATLAS_BASE=/assets/ npm run build`, then `python3 android-offline/prepare_assets.py` (hard-links `dist` into the ignored asset-pack staging directory where possible). From `android-offline/`: `gradle :app:bundleRelease`. Never commit `webassets/src/main/assets/web/`, `.gradle/`, a signing key, or generated AAB/APK. Unsigned release output is not installable; configure release signing **locally** using the same existing certificate for an APK update, and review Google Play App Signing/upload-key enrollment separately. Keep the signing password out of source, Gradle command lines and chat.

This is an **unverified prototype**: this build host currently has only the Android API 23 jar and no Gradle/SDK 36 installation, so an API-36 AAB has **not** been built, installed, tested for edge-to-edge/back behavior, checked with bundletool, or accepted by Play Console. `setFitsSystemWindows(true)` is an initial inset mitigation, not proof of full Android 16 layout compatibility; Android 15/16 device tests, screenshot review, share-target receiving a PNG, backup import/export and in-place upgrade certificate checks remain mandatory. Play’s ~200 MB base-module guidance motivated the pack, but Google Play asset-pack size limits and download behavior must be validated against the actual AAB. Android 16 support is not achieved merely by setting `targetSdk`.
